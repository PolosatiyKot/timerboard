# Таймеры — Cloudflare Worker + D1

Архитектура: браузер → Cloudflare Worker → Cloudflare D1.
Фронтенд (папка `public/`) раздаётся тем же Worker'ом как статика.

Доступ — по трём фиксированным ролям: **admin**, **user**, **viewer**.
Начальные пароли задаются как Cloudflare Secrets, дальше их можно менять
прямо на сайте (администратором).

## Структура

```
timers-app/
├── wrangler.toml       # конфиг Worker'а и биндинг D1
├── schema.sql          # схема базы данных
├── src/worker.js        # backend: авторизация, API таймеров, смена паролей
└── public/              # frontend
    ├── index.html
    ├── style.css
    └── app.js
```

## 1. Установка инструментов Cloudflare

```bash
npm install -g wrangler
wrangler login
```

## 2. База данных D1

Если базы ещё нет:

```bash
wrangler d1 create timers-db
```

Скопируйте выданный `database_id` в `wrangler.toml` вместо
`REPLACE_WITH_YOUR_DATABASE_ID`.

Если база уже создана — возьмите её `database_id` командой `wrangler d1 list`.

## 3. Применение схемы

```bash
wrangler d1 execute timers-db --remote --file=./schema.sql
```

**Важно:** таймеры были переработаны (система/игрок/описание/EVE time +
запуск по длительности с паузой). Эта команда **удаляет** таблицу `timers`
и создаёт её заново — все ранее созданные таймеры будут потеряны. Таблицы
`accounts`/`sessions` при этом не трогаются.

## 4. Пароли ролей — Cloudflare Secrets

Задайте начальный пароль для каждой роли (можно и не для всех сразу —
роль без секрета просто не сможет войти, пока вы его не добавите и не
задеплоите заново):

```bash
wrangler secret put INITIAL_ADMIN_PASSWORD
wrangler secret put INITIAL_USER_PASSWORD
wrangler secret put INITIAL_VIEWER_PASSWORD
```

Каждая команда попросит ввести значение пароля — оно шифруется на
стороне Cloudflare (то же самое, что вы видели в Dashboard → Settings →
Variables and secrets).

Эти секреты используются **только один раз** — при первом обращении к
Worker'у после деплоя он сам считывает их и сохраняет хэш пароля в D1.
Если позже поменять секрет через `wrangler secret put`, это никак не
повлияет на уже сохранённый в базе пароль — это нормально: дальнейшую
смену паролей делает администратор через сайт (раздел «Пароли»).

## 5. Деплой

```bash
wrangler deploy
```

Wrangler выдаст адрес вида `https://timers-app.<ваш-поддомен>.workers.dev`.

## 6. Вход

Откройте сайт и введите пароль — роль на экране входа выбирать не нужно,
она определяется автоматически по тому, какой пароль совпал. Поэтому
**у каждой роли должен быть свой уникальный пароль** — если два секрета
случайно совпадут, войдёт та роль, что проверяется первой.

## Роли и права

| Роль          | Просмотр таймеров | Создание/редактирование/удаление | Смена паролей |
|---------------|:-----------------:|:---------------------------------:|:-------------:|
| Администратор | ✅                 | ✅                                 | ✅             |
| Пользователь  | ✅                 | ✅                                 | ❌             |
| Наблюдатель   | ✅                 | ❌                                 | ❌             |

Администратор меняет пароль любой роли в разделе «Пароли» на сайте —
смена пароля сразу разлогинивает всех, кто был в этот момент под этой
ролью.

## Таймеры

Каждая карточка редактируется прямо на месте (без отдельных окон):
- **Описание**, **Система**, **Игрок**, **EVE time** — свободные текстовые поля.
- **Дни/Часы/Минуты/Секунды** — задают длительность отсчёта. Пока таймер
  остановлен, ниже сразу показывается расчётное время окончания (если
  нажать «Старт» прямо сейчас) — оно живо пересчитывается по мере ввода.
- **Старт (▶)** — запускает обратный отсчёт с указанной длительностью.
- **Пауза (⏸ / ▶)** — при первом нажатии ставит отсчёт на паузу, при
  повторном — продолжает с того же места.
- **Стоп (■)** — останавливает и сбрасывает оставшееся время обратно к
  заданной длительности.
- **Удалить** — убирает карточку.

Карточки на странице отсортированы по возрастанию оставшегося времени:
у кого меньше всего времени — тот сверху/первым.

## Как это устроено

- **Пароли**: в D1 хранится SHA-256(соль + пароль) и сама соль, открытым
  текстом пароли нигде не хранятся — ни в базе, ни в секретах после
  первого запуска.
- **Сессии**: после входа выдаётся cookie `session` (HttpOnly, Secure,
  30 дней), токен живёт в таблице `sessions` в D1.
- **Таймеры**: название, описание (что именно отсчитывается) и целевая
  дата/время. Создавать можно сколько угодно.
